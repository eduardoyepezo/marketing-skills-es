# Tipos de Cliente — Variaciones por Modelo de Negocio

La estructura del plan de 13 secciones se mantiene consistente entre tipos de cliente. Lo que cambia es el **énfasis de contenido** dentro de cada sección. Este documento nombra los patrones dominantes por arquetipo de cliente.

## Arquetipo 1 — B2B SaaS

### Características principales
- Ingreso por suscripción
- A menudo ACV más alto ($1K–$100K+ al año)
- Asistido por ventas o self-serve dependiendo del nivel
- El comprador a menudo es distinto del usuario (champion vs. usuario final)

### Énfasis AARRR

**Adquisición pesada:**
- El SEO es el motor dominante de tope de funnel (la gente busca soluciones)
- El content marketing (blog, base de conocimiento, páginas de comparación) genera MQLs
- LinkedIn tanto para presencia orgánica del founder como para pago
- El outbound (cold email + LinkedIn) a menudo complementa al inbound
- Eventos (conferencias, webinars) para productos de ACV alto

**Activación:**
- Signup → trial → primera acción clave (productos PLG)
- Trial → demo → POC (productos sales-led)
- Los estados vacíos importan — guían a los usuarios hacia la primera acción de valor

**Retención:**
- Métricas de engagement de producto (DAU, adopción de funciones)
- Motion de customer success (equipo de CSM para ACV más alto)
- Emails de lifecycle enfocados en descubrimiento de funciones, momentos de valor

**Referidos:**
- Programas de advocacy de clientes
- Co-marketing de partners / integraciones
- Reseñas en G2 / Capterra
- Expansión de champion a comprador

**Ingresos:**
- La expansión / NRR es a menudo la mayor palanca de crecimiento
- Upgrades de nivel, expansión de asientos, add-ons por uso

### Énfasis de skills
- `cold-email`, `programmatic-seo`, `competitor-alternatives`, `seo-audit`, `ai-seo`
- `paid-ads` ponderado hacia LinkedIn + Google
- `email-sequence` para nurture de trial + lifecycle
- `pricing-strategy` para optimización de niveles

### Prioridad de presupuesto Tier 1
- SEO + contenido > todo lo demás
- Canal de LinkedIn liderado por el founder
- Customer.io / Mailchimp para nurture
- HARO + backchannel de inversionistas para PR

## Arquetipo 2 — App de Consumo D2C (Suscripción)

### Características principales
- ACV más bajo ($5–$30/mes típicamente)
- Alto volumen, margen más bajo por usuario
- App Store / Play Store como la superficie principal de adquisición
- Email de lifecycle + push para retención
- A menudo impulsado por adquisición pagada una vez que se desbloquea presupuesto

### Énfasis AARRR

**Adquisición:**
- La optimización de App Store (ASO) es el activo no-sitio de mayor apalancamiento
- Paid social (Meta, TikTok) a menudo dominante una vez que existe presupuesto
- Apple Search Ads para tráfico de App Store de alta intención
- Influencers + creadores de contenido
- PR + endorsements

**Activación:**
- El onboarding es la superficie de activación dominante
- El time-to-value debe ser en minutos, no horas
- La estructura de paywall + duración del trial es crítica

**Retención:**
- Email de lifecycle + push
- Recordatorios in-app (con cuidado — el exceso = churn)
- Centro de preferencias de suscripción
- Campañas de win-back

**Referidos:**
- Compartir integrado (flujo de compartir-un-mes)
- Referidos de dos lados
- Influencers / creadores como ambassadors

**Ingresos:**
- El default de plan anual es la mayor movida individual (comprime el MRR pero mejora el LTV)
- Optimización de niveles (Free → Premium → Premium+)
- Upsells in-app

### Énfasis de skills
- `onboarding-cro`, `paywall-upgrade-cro`, `email-sequence`
- `paid-ads`, `ad-creative` (iteración creativa pesada)
- `referral-program`
- `pricing-strategy` para default anual + consolidación de niveles

### Prioridad de presupuesto Tier 1
- ASO primero (mayor apalancamiento orgánico)
- Reconstrucción del onboarding
- Envío de lifecycle de email
- Social liderado por el founder si el founder está en cámara

## Arquetipo 3 — Híbrido Hardware + Software

### Características principales
- Producto físico + compañero de software (p. ej., el antifaz para ojos + app de Quietude)
- El hardware como cuña de distribución (precio más bajo, primera compra más fácil)
- El software como el LTV (ingreso recurrente)
- CAC blended a través de ambas superficies

### Énfasis AARRR

**Adquisición:**
- SEO del storefront de Shopify (las páginas del producto de hardware apuntan a búsqueda de consumo)
- Listado en Amazon (alto descubrimiento, se lleva margen)
- Amplificación de PR (el hardware es fotogénico — endorsements de influencers de alto perfil mueven volumen)
- Paid social para hardware (Meta + Instagram, creatividad llamativa)

**Activación:**
- Dos activaciones que rastrear: experiencia de unboxing del hardware + signup de software
- El flujo de activación hardware → software es el puente
- Configuración concierge para compradores de hardware de alto valor

**Retención:**
- Lifecycle post-compra de hardware (distinto del onboarding de app)
- El compañero de software impulsa la pegajosidad (stickiness)
- Comunidad / red de practicantes alrededor del hardware

**Referidos:**
- Flujos de regalo de hardware (alto boca a boca para productos físicos)
- El hardware llamativo impulsa el compartir social orgánico
- Reseñas en Shopify + Amazon

**Ingresos:**
- Las matemáticas de LTV blended son críticas (margen de hardware + recurrencia de software)
- Estrategia de bundle (compra de hardware → Premium gratis por X meses)
- Default de plan anual para el software

### Énfasis de skills
- `seo-audit` para páginas de producto de Shopify
- `email-sequence` tanto para post-compra de hardware como lifecycle de software
- `referral-program` con capa de regalo
- `pricing-strategy` para matemáticas de bundle blended
- `paid-ads` con presencia creativa pesada en Meta

### Prioridad de presupuesto Tier 1
- Optimización de la página de producto de Shopify
- Envío del lifecycle post-compra de hardware
- Formalización de la estrategia de bundle
- Auditoría de activación hardware → app

## Arquetipo 4 — Marketplace

### Características principales
- Producto de dos lados (oferta + demanda)
- Los efectos de red importan
- La liquidez es la métrica crítica temprana
- Take-rate × GMV es el modelo de ingresos

### Énfasis AARRR

**Adquisición:**
- Dos funnels — oferta y demanda
- La oferta a menudo se adquiere vía outbound / partnership / cold email
- La demanda a menudo se adquiere vía SEO / pago / contenido
- SEO programático ciudad por ciudad es común

**Activación:**
- Activación de oferta: primer listado publicado, primera respuesta enviada
- Activación de demanda: primera compra / primer match / primera transacción
- Ambos lados necesitan su propio onboarding

**Retención:**
- Frecuencia de transacción recurrente
- Utilización de oferta (% de listados activos)
- Hábito de demanda (DAU / MAU)

**Referidos:**
- Oferta → oferta (referir a otros proveedores)
- Demanda → demanda (referir a otros compradores)
- Los referidos entre lados son más débiles

**Ingresos:**
- Optimización de take-rate
- Nivel premium (mejor matching, comisiones más bajas)
- Monetización por lead-gen vs. comisión por transacción

### Énfasis de skills
- `programmatic-seo` para páginas de ciudad, páginas verticales
- `cold-email` para reclutamiento del lado de la oferta
- `referral-program` para ambos lados
- `pricing-strategy` para decisiones de take-rate

### Prioridad de presupuesto Tier 1
- Construcción de SEO programático para un lado
- Outbound en frío para sembrar oferta (o demanda, el que sea el cuello de botella)
- Email de lifecycle para ambos lados

## Arquetipo 5 — Herramienta para Desarrolladores / Open Source

### Características principales
- Comprador técnico (desarrollador o líder de ingeniería)
- Barra alta de calidad de contenido (los desarrolladores son escépticos)
- El DevRel importa más que el marketing tradicional
- La capa open source a menudo funciona como funnel hacia el producto comercial

### Énfasis AARRR

**Adquisición:**
- Contenido técnico + SEO de documentación
- DevRel (conferencias, charlas, comunidad)
- Presencia en GitHub + descubrimiento vía npm/pip/etc.
- Hacker News + Reddit + Twitter de desarrolladores

**Activación:**
- El primer build / primera integración es el evento de activación
- El time-to-Hello-World importa
- La documentación = onboarding para herramientas de desarrolladores

**Retención:**
- Profundidad de integración (usar más del producto)
- Adopción por equipo (un usuario → toda la organización)
- Conteo de proyectos activos

**Referidos:**
- Conteo de estrellas en GitHub (semi-orgánico)
- Recomendación en foros técnicos
- Charlas en conferencias que mencionan la herramienta

**Ingresos:**
- Conversión gratis → pago cuando el uso excede los límites
- Planes de equipo, niveles enterprise
- Upsells de soporte / SLA

### Énfasis de skills
- `programmatic-seo` para documentación
- Menos énfasis en `paid-ads` tradicional
- `content-strategy` pesado + contenido técnico
- `cold-email` a líderes de ingeniería en empresas objetivo

### Prioridad de presupuesto Tier 1
- Producción de documentación + contenido técnico
- DevRel (el founder dando charlas)
- Presencia en GitHub
- HN / Reddit / comunidad de desarrolladores

## Arquetipo 6 — Deep-Tech / Científico / Clínico

### Características principales
- Ciclos de venta largos
- Alta carga de credibilidad (hay que probar la ciencia)
- Compradores muy informados (académicos, clínicos, investigadores)
- A menudo consideraciones regulatorias

### Énfasis AARRR

**Adquisición:**
- Publicaciones académicas + estudios peer-reviewed
- Charlas en conferencias (académicas + de industria)
- Presentaciones de inversionistas / advisors
- PR vía ganchos de credibilidad

**Activación:**
- Programas piloto / pruebas de concepto
- Configuración concierge con onboarding de alto contacto
- Webinars educativos / capacitaciones

**Retención:**
- Customer success intensivo
- Co-publicación con clientes
- Comunidad de práctica

**Referidos:**
- Referencias académicas / clínicas
- Apariciones en paneles de conferencias
- Casos de estudio con instituciones nombradas

**Ingresos:**
- Expansión de piloto a pago
- Contratos institucionales (multi-asiento / multi-año)
- Upsells de compliance / certificación

### Énfasis de skills
- Marketing tradicional ligero
- `product-marketing-context`, `sales-enablement`, `pricing-strategy` pesados
- `cold-email` a investigadores / practicantes específicos
- PR + marketing a inversionistas

### Prioridad de presupuesto Tier 1
- Outreach académico + charlas en conferencias
- Backchannel de inversionistas para intros institucionales cálidas
- Despliegue piloto con clientes clave
- Caso de estudio + publicación científica

## Arquetipo 7 — Comercio / DTC (no-suscripción)

### Características principales
- Productos físicos o digitales vendidos transaccionalmente
- El Average Order Value importa
- La tasa de recompra es la métrica clave de retención

### Énfasis AARRR

**Adquisición:**
- Paid social (Meta, TikTok) a menudo dominante
- SEO de Shopify para páginas de producto
- Listados en Amazon
- Partnerships con influencers y creadores

**Activación:**
- La primera compra es el evento de activación
- Recuperación de carrito abandonado
- Señales de confianza en el checkout (reseñas, devoluciones, envío)

**Retención:**
- Lifecycle post-compra
- Programas de lealtad
- Email + SMS para recompra

**Referidos:**
- Flujos de regalo
- Programas de refiere-a-un-amigo
- Reseñas + UGC

**Ingresos:**
- Optimización de AOV (bundles, upsells)
- Optimización del LTV de cliente (frecuencia de recompra)
- Opción de suscripción para compras recurrentes

### Énfasis de skills
- `paid-ads` + `ad-creative` (peso pesado)
- `email-sequence` para post-compra + carrito abandonado
- `referral-program` con regalos
- `pricing-strategy` para bundles + opción de suscripción

### Prioridad de presupuesto Tier 1
- Optimización del storefront de Shopify
- Envío del lifecycle de email
- Seeding de influencers / UGC
- Pruebas de paid social (si existe presupuesto mínimo)

## Cómo usar este documento al redactar un plan

Cuando comiences a redactar las Secciones 4–8 (AARRR), identifica el arquetipo del cliente (o híbrido si aplica) e inclínate hacia los patrones de arriba.

**Los casos híbridos son comunes.** Quietude es "Híbrido hardware + software" con superposición significativa con "Deep-tech / científico / clínico" (por su posicionamiento de estudio peer-reviewed + clínico). El plan mezcla énfasis de ambos arquetipos.

Ante la duda, lidera con el arquetipo que mejor se ajuste al *modelo de monetización primario*. La monetización primaria de Quietude es la suscripción de software (con el hardware como cuña), así que dominan los patrones de app de consumo D2C + híbrido de hardware, con movidas de credibilidad deep-tech en capas.

## Cuando el cliente no encaja limpiamente

Algunos clientes desafían el arquetipo:
- **Negocios de contenido / medios** — ni SaaS ni comercio; modelo de ingreso por publicidad o suscripción
- **Redes sociales** — categoría propia, dominan los efectos de red
- **Bienes raíces / eventos** — modelo físico + de servicio

Para estos, identifica el arquetipo más cercano y ajusta. No fuerces el encaje — nombra la desviación en el Marco Estratégico del plan.
